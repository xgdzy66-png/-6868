# TG Atelier 多账号 AI 管家后台

用户目标：将现有普通 Telegram 账号 AI 群聊脚本升级为可在 Windows WSL2 和 Linux 服务器直接运行的网页后台，集中配置并登录多个账号，提供多个 AI 功能。

## 实现方式

在现有 `ai-chat` 内新增独立 `tg_console` 包，复用 `tg_ai` 的群聊引擎、SQLite 上下文、AI 客户端和限流逻辑，不改变仓库原库存机器人业务或部署。

后台采用 FastAPI + 原生模块化 HTML/CSS/JavaScript，同源提供页面和 API。只需要 Python 环境，不需要用户另装 Node。自建服务器先绑定本机环回地址，远程管理默认通过 SSH 隧道；演示预览不能登录真实 Telegram 或保存真实凭据。

后台认证方案等待用户确认：推荐本地管理员密码，首次通过终端设置，密码仅存慢哈希；若用户选择 Manus，则需要相应 OAuth 配置，不能静默替换。

配置向导将 Telegram API ID/API Hash、AI 服务地址、模型、密钥集中配置。未知真实凭据不预填、不从任务环境分发。密钥使用本机独立 Fernet 主密钥加密，API 响应只返回是否已配置；账号 session 文件保存在受限目录，不提供网页下载。验证码和两步验证密码仅用于当前登录步骤，不持久保存。

每个账号独立登录状态：未登录、等待验证码、需要两步验证、已登录、运行中、暂停、连接失败。首次必须按 Telegram 正常验证流程逐账号登录；保存会话后可一键连接或一键启动已选择的账号。操作采用有界并发，错误逐账号反馈，不把成功账号当失败重试。

每个账号独立配置群白名单、AI 人设、自动聊天开关、mentions/smart/all 模式、回复概率、冷却、配额和试运行。自动聊天仅针对白名单群。默认试运行，不默认开启真实发送。阻止同一 Telegram 用户被重复添加；默认阻止本机多个运行账号自动参与同一群，以免互相触发。

AI 功能包含：上下文群聊；FAQ 人设问答；人工输入或本机群上下文的摘要；翻译；文本润色。工作台输出均为草稿，不自动发送到 Telegram。自动摘要广播和定时群发不在本次范围。

控制台提供账号列表、登录向导、群选择、批量连接/启动/停止、运行状态、受保护的近期草稿与结构化事件记录。断开是本机停止连接，不撤销 Telegram 授权会话；永久撤销仍由用户在 Telegram 设备设置执行。

## 目录结构

- `tg_ai/`：已存在的单账号引擎和 AI 接口，继续支持原 CLI。
- `tg_console/vault.py`：加密配置、账号元信息、审计事件。
- `tg_console/manager.py`：多账号登录、独立 Telethon 客户端、运行生命周期。
- `tg_console/security.py`：管理员认证、会话、CSRF 和登录限流，按确认方案实现。
- `tg_console/server.py`：FastAPI 路由、输入校验、统一安全错误响应。
- `tg_console/static/`：后台页面、样式与前端交互。
- `tg_console/__main__.py`：初始化和启动入口。
- `tests/`：新增后台权限、加密、登录状态、批量操作和工具功能测试。
- `start-dashboard.sh`、`tg-ai-dashboard.service`：Windows WSL2 / Linux 可用的启动和常驻模板。

## 视觉方案

采用现代瑞士信息设计与精密仪表盘风格。品牌为 TG Atelier：一个让多个 AI 管家有序工作的私有控制台。品牌性格为克制、可信、灵活。

原则：重要状态先于装饰；密钥默认不可见；每次批量操作清晰说明对象与结果；强操作与试运行状态有明确区别。

配色为浅雾灰背景、墨蓝正文和电光蓝品牌强调色；绿色仅用于已验证运行状态，琥珀色用于待验证与暂停。避免让未登录账号显示为正常在线。

布局采用固定细侧栏、顶部环境状态与宽工作区。主工作区是左侧账号列表加右侧账号详情的主从布局，不用通用大卡片堆叠。工具工作台使用输入/输出双栏。

标志为两个交错的括号组成的 A 字形标记；使用现有图标字体或开源线性图标，不添加无关插画。字体为系统中文无衬线搭配 Inter/系统英文字体，数字与状态可用等宽字体。

核心文案：「每个账号，各有分工。」「先验证，再上线。」「已保存会话，一键连接。」明确说明「演示」与「真实运行」，不制造在线数量。

交互使用 140—200ms 的轻量过渡，表单逐步骤显示，操作成功以就近反馈与状态更新体现；不使用大范围装饰动画。小屏侧栏折叠，账号详情改为全宽。
